# PRD: Meeting File Upload and Display

**Дата**: 2026-08-17
**Статуы**: Draft

## Цель

Дать создателю встречи возможность прикрепить аудио/видео-файлы записи к встрече, надёжно сохранить их для последующей обработки (например, транскрибации в будущей итерации) и просматривать список прикреплённых файлов на странице встречи.

## Пользовательские сценарии

- Пользователь открывает страницу своей встречи -> видит список уже прикреплённых файлов записи (если есть).
- Создатель встречи выбирает и загружает аудио/видео-файл на странице встречи -> файл сохраняется и появляется в списке файлов встречи со статусом загрузки.
- Создатель встречи загружает ещё один файл к той же встрече -> файл добавляется в список, предыдущие файлы не удаляются.
- Создатель встречи пытается загрузить файл недопустимого формата или превышающий лимит размера -> видит понятную ошибку, файл не сохраняется.
- Пользователь, не являющийся создателем встречи, открывает страницу встречи -> видит список файлов, но не видит возможность загрузки.
- Во время загрузки файла пользователь видит прогресс/индикатор загрузки и не может повторно отправить тот же файл повторным нажатием.

## В скоупе

- Страница деталей встречи `/meetings/[id]` (ранее отсутствовала — есть только `/meetings/new`), доступная авторизованным пользователям.
- Отображение основной информации о встрече (title, date, participants) на этой странице.
- Блок загрузки файла на странице встречи, видимый и активный только для создателя встречи.
- Поддержка множественной загрузки: у одной встречи может быть несколько прикреплённых файлов записи.
- Список прикреплённых файлов на странице встречи: имя файла, дата загрузки, размер, статус.
- Валидация на клиенте и сервере: допустимые аудио/видео форматы (mp3, wav, m4a, mp4) и максимальный размер файла.
- Серверное хранение файла и связанных метаданных (имя, размер, mime-type, встреча, кто загрузил, дата) для последующей обработки другой фичей.
- Добавление поля владельца/создателя (`creatorId`) к модели `Meeting`, так как сейчас у встреч нет владельца — необходимо для проверки прав на загрузку.
- Обработка и отображение ошибок загрузки (недопустимый формат, превышение размера, сетевая ошибка, файл не найден на сервере).
- Индикатор процесса загрузки (progress/pending state) в UI.

## Не в скоупе

- Сама обработка файла (транскрибация, распознавание речи, анализ содержимого) — только сохранение файла в состоянии, готовом для передачи в будущий процесс обработки.
- Скачивание/потоковое воспроизведение файла из UI встречи.
- Удаление или замена уже загруженных файлов.
- Редактирование метаданных встречи на странице деталей (title/date/participants) — только просмотр.
- Права участников (не-создателей) на загрузку файлов.
- Уведомления (email/push) о завершении загрузки или обработки.
- Хранение нескольких версий одного и того же файла / история изменений.

## Технические ограничения

- В текущей схеме Prisma у `Meeting` нет поля владельца — потребуется миграция, добавляющая `creatorId`, и обратное проставление владельца для уже существующих встреч (или явное решение, что старые встречи без владельца не позволяют загрузку).
- `GET /meetings` сейчас не привязан к пользователю (глобальный список без сортировки на сервере) — это не блокирует фичу, но подтверждает отсутствие текущей модели прав доступа.
- В проекте пока нет интеграции с файловым хранилищем (ни локального, ни облачного) — конкретный backend хранения определяется на этапе технического дизайна, а не в этом PRD.
- Загрузка больших аудио/видео файлов через стандартный JSON body недопустима — потребуется multipart/streaming загрузка; конкретная реализация — предмет технического дизайна.
- Максимальный размер файла и точный список допустимых форматов должны быть зафиксированы как конфигурируемые константы (не хардкод в нескольких местах).

## Критерии готовности

- [] Создатель встречи может открыть `/meetings/[id]` и увидеть блок загрузки файла.
- [] Пользователь, не являющийся создателем встречи, открывает `/meetings/[id]` и не видит элемент загрузки файла.
- [] Загрузка файла в допустимом формате (mp3, wav, m4a, mp4) и в пределах лимита размера завершается успешно, файл появляется в списке файлов встречи без перезагрузки страницы.
- [] Загрузка файла недопустимого формата отклоняется с понятным сообщением об ошибке, файл не сохраняется на сервере.
- [] Загрузка файла, превышающего максимальный размер, отклоняется с понятным сообщением об ошибке до завершения полной передачи файла.
- [] К одной встрече можно прикрепить более одного файла — они все отображаются в списке.
- [] При открытии страницы встречи с уже загруженными файлами список файлов (имя, размер, дата загрузки) отображается корректно.
- [] Неавторизованный запрос на загрузку файла (без валидного токена) отклоняется с 401.
- [] Во время загрузки в UI отображается индикатор процесса, повторная отправка того же файла заблокирована до завершения текущей загрузки.
- [] Метаданные и сам файл сохраняются так, что их можно однозначно связать со встречей (для использования будущей фичей обработки).
