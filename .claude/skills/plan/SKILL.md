# plan генератор

Прочитай PRD из файла: $ARGUMENTS

Сохрани результат в файл 'docs/plan-$ARGUMENTS.md' (используй перевод на английский и kebab-case)

Если нет папки /docs создай ее

## Структура плана

# Plan: {Название фитчи}

**PRD**: $ARGUMENTS
**Дата**: {Текущая дата}

## Фазы реализации

### Фаза 1: {название}
**Цель**: Что дает эта фаза
**Затрагивает**: backend/fronend/database 
**Задачи**:
- [] Задача 1
- [] Задача 2
**Критерии готовности**: конкретный критерий

### Фаза 2: {название}
...

## Правила разбивки на фазы
- Каждая фаза должна давать рабочий результат
- Фазы независимы, можно остановить на любой
- Первая фаза как минимальный рабочий путь (Tracer Bullet)
- Не больше 5 задач в одной фазе
- Backend и frontend одной фичи это разные фазы

## Правила
- Читай PRD внимательно, план должен покрывать все критерии готовности
- Не добавляй задачи которых нет в PRD
- Если PRD не полный, задай вопрос перед созданием плана
